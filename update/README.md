# ローザ ver1.3 改修版

元のver1.3のゲーム進行をベースに、写真撮影の内外カメラ切り替え、Hiroマーカー認識、ピンクの花びら演出を追加した試作版です。独自の缶バッジ用マーカー・対象スマートフォンは未確定です。

## 起動

1. このフォルダで `python -m http.server 5500 --bind 127.0.0.1` を実行するか、VS Code Live Serverを起動します。
2. PCで `http://localhost:5500/index.html` を開きます。HTMLの直接ダブルクリックでは起動しないでください。
3. スマートフォンではHTTPSの配信先に配置して開きます。PCのlocalhostをスマートフォンからそのまま利用することはできません。公開・アップロードは今回実施していません。
4. Bootstrap 5.3.0、A-Frame 1.4.2、Draco復号器は外部配信なのでネット接続が必要です。カメラ映像・撮影画像をアップロードする処理はありません。

配信するもの: `index.html`, `camera.js`, `media.js`, `ar-effects.js`, `roza.glb`, `frame.svg`, `assets/`。検証用マーカーの案内も配信する場合は `marker.html` を含めてください。
`backup/`, `tests/`, 元の依頼メモ、TODO.md、.DS_Storeはアプリの実行に不要です。

## 操作

- 最初の「tap」でモデルの準備を待ち、会話を読み進めます。画面ドラッグで周囲を探し、妖精をタップすると全3段階で進みます。
- ゲーム中、左上の「ARを開始」を押してカメラを許可します。背面カメラを優先します。
- [検証用Hiroマーカー](marker.html) を印刷または別画面に表示し、黒枠全体と外側の白い余白が映るようにかざします。添付されたバラの画像自体を認識する設定にはなっていません。
- マーカーが見えている間、毎秒12枚の花びらを生成します。生存期間3.2秒、最大48枚。見失うと花びらを消し、再検知すると再開します。再検知でも生成間隔は1秒以上です。
- 妖精は元のゲーム座標で表示し、花びらだけがマーカー位置に追従します。スキャン枠・読み取り案内UIは表示しません。
- 3回発見すると、ARと3D処理を停止して写真画面へ進みます。右上でイン／アウトカメラを切り替えられます。
- 映像とフレームが準備できるまで撮影ボタンは無効です。カメラ失敗・フレーム失敗時は「再試行」を使います。
- 写真は表示と同じ中央切り抜き・フレーム配置で1027×1180のPNGになります。インカメラは表示・保存とも鏡像、アウトカメラは正像です。
- 保存ボタンまたは画像の長押し／右クリックで保存できます。「撮影を終了」でカメラを停止します。タブを隠した際にもカメラを停止し、復帰後は明示的に再試行します。

## 仮設定・差し替え

- `ar-effects.js` 冒頭の `AR_CONFIG` にマーカーURL、発生間隔、枚数、寿命をまとめています。
- 今回はAR.jsのパターンマーカー方式を選択しました。独自 `.patt` と対応する枠付き印刷原稿へ差し替え可能です。枠なしのバラ画像をそのまま認識させたい場合は、MindAR等の画像認識方式への切り替えと認識データ生成が別途必要です。
- 花びらは参照画像のピンク色・淡い色味を参考に、コードで輪郭・反り・色を付けた軽量メッシュです。添付画像の切り抜きや動画素材の転載ではなく、見た目を確認するための試作です。原画の水彩タッチに忠実な仕上げは、赤線のない原素材と採用範囲を確認して調整します。
- カメラが1台のみ等で切り替え先がない場合は元のカメラへの復帰を試み、理由を表示します。ブラウザが返すカメラ方向情報がない場合は要求した方向を使用します。
- スマートフォンのセンサー操作・カメラ固有の挙動、印刷物の反射・距離・角度は実機確認が必要です。

## 検証

- `node tests/camera.test.cjs`: 3種類の縦横比の中央切り抜き、不正寸法、遅延した許可応答の破棄、競合リクエスト、トラック解放。
- `http://localhost:5500/tests/browser.html`: 実カメラを使わず、canvasのテスト映像でアプリを動かす統合テストです。「テスト開始」で初期化し、各自動テストの前に再度初期化してください。
- 撮影テスト: PNG生成、カメラ切り替え、ミラー切り替え、元ストリームの解放、切替先欠落からの復帰、権限拒否、再試行、撮影終了。
- 認識テスト: AR.jsへHiro画像を含む実フレームを渡して検知し、花びらの生成・上限、検知喪失・再検知、写真移行時の停止を確認します。検知イベントを偽装するテストではありません。ただし実カメラ・印刷物の試験ではありません。
- ゲーム進行テスト: GLB読込、手動会話送り、3段階の進行、古い会話の非表示、写真画面での3D停止。発見操作はクリックイベントで試験するため、実画面のレイキャスト精度は別途確認してください。
- 検証画面・結果は `tests/` に保存します。デスクトップ内蔵ブラウザでのテスト結果であり、iPhone/Androidの実機合格を意味しません。

## 追加で必要な情報

1. 実物の缶バッジの印刷画像・寸法・既存認識データ。黒枠を付けられるか。
2. 対象端末・OS・ブラウザ・HTTPS公開先。
3. 花びらの最終的な枚数・速さ・広がり方、1回再生か連続再生か、見失った後も最後まで流すか。
4. 原画素材の採用範囲と赤線のない原本。
